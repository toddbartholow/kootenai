API Reference

The Kootenai API provides RESTful endpoints for managing labs, pods, sessions, and achievements.

Base URL: http://localhost:8080 (development) or your deployed API URL

Authentication: Most endpoints require a JWT token in the Authorization: Bearer <token> header.

Health & Status​

GET /health​

Basic liveness check.

Response:

{
  "status": "ok"
}

GET /health/live is an alias. "ok" is the only value this endpoint ever returns.

GET /ready​

Readiness check with service status. GET /health/ready is an alias.

Response (200 when healthy, 503 when degraded):

{
  "status": "healthy",
  "version": "1.0.0",
  "uptime": "3h12m4s",
  "checks": {
    "database": { "status": "healthy", "latencyMs": 2 },
    "nats": { "status": "healthy", "latencyMs": 1 },
    "redis": { "status": "healthy", "latencyMs": 1 },
    "proxmox": { "status": "healthy", "circuitState": "closed", "failures": 0 }
  }
}

Top-level status is only ever healthy or degraded. A doc comment in the source also mentions unhealthy, but no code path sets it at the top level.

The circuit field is circuitState (camelCase), not circuit_state, and takes closed, half-open or open. Per-check status is healthy or unhealthy, except proxmox, which adds not_configured (the default) and recovering (circuit half-open). Proxmox and CloudStack failures deliberately do not flip the top-level status — a dead hypervisor leaves the API healthy, because the API is still able to serve.

GET /version​

API version information.

Response — note the mixed casing: build_time and go_version are snake_case while the rest are not (api/internal/version/version.go:19-27):

{
  "version": "1.0.0",
  "commit": "abc1234",
  "build_time": "2025-01-07T12:00:00Z",
  "go_version": "go1.24",
  "os": "linux",
  "arch": "amd64",
  "edition": "community"
}

edition is always community in any build produced from this repository.

Authentication​

:::caution There are no refresh tokens The platform issues a single JWT. /auth/refresh re-issues one of the same kind and requires a token that is still valid. See Authentication for the full picture. :::

POST /api/v1/auth/login​

Authenticate and receive a JWT.

Request — the field is email, not username:

{
  "email": "user@example.com",
  "password": "password123"
}

Response:

{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "name": "John Doe",
    "roles": ["student"],
    "iat": 0,
    "defaultOrgId": "org-uuid"
  },
  "mustChangePassword": false
}

name not displayName; roles array not role string; no expiresIn. The user object's iat is never assigned and is always 0.

POST /api/v1/auth/refresh​

Exchange a still-valid JWT for a new one.

Request — the field is token, not refreshToken. Sending refreshToken decodes to an empty value and fails as though the body were empty:

{
  "token": "eyJhbGciOiJIUzI1NiIs..."
}

Response: { "token": "...", "user": { ... } }. No mustChangePassword, and the rebuilt user omits defaultOrgId.

GET /api/v1/auth/me​

Get current authenticated user. The user is nested under a user key:

Response:

{
  "user": {
    "id": "uuid",
    "email": "user@example.com",
    "name": "John Doe",
    "roles": ["student"],
    "iat": 0,
    "defaultOrgId": "org-uuid"
  },
  "preferredLocale": null
}

There are no createdAt or lastLoginAt fields. PUT /api/v1/auth/me/preferred-locale updates the locale.

POST /api/v1/auth/password/reset-request​

Request a password reset email.

Request:

{
  "email": "user@example.com"
}

POST /api/v1/auth/password/reset-confirm​

Confirm password reset with token.

Request:

{
  "token": "reset-token-from-email",
  "newPassword": "newpassword123"
}

POST /api/v1/pods​

Create a new pod from a lab template. 201 Created.

Request — the two fields are labTemplate and owner, and both are required. There is no labTemplateId or name in the request; the pod name is generated server-side (api/internal/server/pods/handlers.go:47-50):

{
  "labTemplate": "linux-basics-101",
  "owner": "jsmith"
}

Response — the full models.Pod, unwrapped:

{
  "id": "uuid",
  "name": "cryptic-waddling-rain",
  "labTemplateId": "uuid",
  "labTemplate": "linux-basics-101",
  "platform": "proxmox",
  "ownerId": "user-uuid",
  "owner": "jsmith",
  "status": "provisioning",
  "vms": [],
  "networks": [],
  "createdAt": "2025-01-07T00:00:00Z"
}

A missing field returns 400 with {"error":"validation failed","details":[{"field":"...","message":"..."}]}.

POST /api/v1/pods/async​

Same request body; returns 202 Accepted immediately with {podId, requestId, status, subject, message}, where subject is the NATS subject carrying provisioning progress.

POST /api/v1/sessions​

Start a new lab session. 201 Created.

Request — three required fields, not one (api/internal/server/sessions/handlers.go:363-373):

{
  "podId": "uuid",
  "userId": "user-uuid",
  "labTemplate": "linux-basics-101"
}

userId is required and then overwritten with the authenticated caller's ID. Optional Canvas fields: canvasAssignmentId, canvasCourseId, canvasUserId, enrollmentId, moduleId.

Response — an acknowledgement, not the session object:

{
  "sessionId": "uuid",
  "status": "started",
  "maxPoints": 100,
  "agentStatus": {}
}

Returns 409 if a live session already exists for that pod.

List all achievements. Query parameters: type, tier, active.

WebSocket Endpoints​

GET /api/v1/ws​

General WebSocket for real-time updates. The routes are registered inside r.Route("/api/v1", ...), so both carry the prefix — /ws on its own is a 404.

Event types (the type field of the {type, subject, payload} envelope): checkpoint, session, grade, assessment, pod_provisioning, hint_nudge, monitoring_event. There are no dotted names such as pod.status, and no achievement events are broadcast.

Auth: Authorization header, a single dot-joined access_token.<jwt> entry in Sec-WebSocket-Protocol, or the auth_token cookie. ?token= is ignored.

GET /api/v1/ws/:podID​

Pod-specific WebSocket. Accepts an optional ?sessionId=.

DELETE /api/v1/teams/:teamID​

POST /api/v1/teams/:teamID/members​

Features​

Feature flags control access to edition-specific functionality.

GET /api/v1/features​

List all available features with edition requirements.

Response:

{
  "features": [
    {
      "id": "teams",
      "name": "Teams Support",
      "description": "Create and manage teams within organizations",
      "editions": ["professional", "enterprise"],
      "category": "collaboration"
    },
    {
      "id": "custom_labs",
      "name": "Custom Lab Templates",
      "description": "Create organization-specific lab templates",
      "editions": ["professional", "enterprise"],
      "category": "labs"
    }
  ]
}

GET /api/v1/organizations/:orgID/features​

Get features and their enabled status for an organization.

Response — a bare array, not an object with features and edition keys (api/internal/server/features/features.go:136-148). Feature ids are dotted, not underscored:

[
  { "id": "teams", "name": "Team Management", "description": "...", "enabled": true, "editions": ["professional", "enterprise"], "isGlobal": false },
  { "id": "labs.custom", "name": "Custom Lab Templates", "description": "...", "enabled": true, "editions": ["professional", "enterprise"], "isGlobal": false },
  { "id": "sso.saml", "name": "SAML SSO", "description": "...", "enabled": false, "editions": ["enterprise"], "isGlobal": false }
]

A global catalogue is also served at GET /api/v1/features.

POST /api/v1/organizations/:orgID/features/:featureID​

Enable or disable a feature override (admin only).

:::caution The method is POST, not PUT api/internal/server/features/routes.go:15-19 registers GET /features, POST /features/{featureID} and DELETE /features/{featureID}. There is no PUT on this route — a PUT returns 405. :::

Response: { "featureId": "teams", "enabled": true, "expiresAt": null }

DELETE /api/v1/organizations/:orgID/features/:featureID​

Remove the organization's override, falling back to the edition default.

Response: { "featureId": "teams", "message": "feature override removed" }

Classroom Simulation (Enterprise)​

AI classroom simulation endpoints for orchestrating virtual students. Requires ai_classroom enterprise feature.

For full endpoint documentation, see Classroom Simulation API.

POST /api/v1/simulation/classrooms​

Create a new simulation with auto-generated AI students.

GET /api/v1/simulation/classrooms​

List all simulations.

GET /api/v1/simulation/classrooms/:id​

Get simulation details with students.

POST /api/v1/simulation/classrooms/:id/start​

Start a pending/paused simulation.

POST /api/v1/simulation/classrooms/:id/pause​

Pause a running simulation.

POST /api/v1/simulation/classrooms/:id/stop​

Stop a simulation.

DELETE /api/v1/simulation/classrooms/:id​

Delete a simulation (cascades to students and activities).

GET /api/v1/simulation/classrooms/:id/activities​

Paginated activity feed (query params: limit, offset).

GET /api/v1/simulation/classrooms/:id/students/:studentId​

Get AI student details including runtime state.

Rate Limiting​

The API implements rate limiting:

  • General: 100 requests/minute per IP
  • Pod Creation: 10 pods/hour per user
  • Login: 5 attempts/minute per IP

Rate limit headers are included in responses:

X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1704628800
